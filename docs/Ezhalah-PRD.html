Executive summary

Saudi renters and buyers today juggle six or more separate property apps — Aqar, Bayut, Gathern, Property Finder, Wasalt and Aldarim — each with its own search, filters and listings. Finding the right property means repeating the same search across every app and mentally de-duplicating the results.

Ezhalah collapses that into a single, AI-native search. A user describes what they want in plain language (Arabic or English) — or answers a short guided interview — and Ezhalah returns a ranked, unified set of listings sourced from all connected platforms. Tapping any result opens the original listing on its source platform, sending that platform a qualified, high-intent visitor.

Positioning

Ezhalah is a search and discovery layer only. It does not own, list, sell, rent, or transact any property, and it takes no commission. It is a neutral aggregator that benefits users (one search) and partner platforms (qualified traffic) alike.

01

Overview & vision

Vision

"Type what you want. Ezhalah searches every major Saudi property platform and brings the matches back in seconds."

Ezhalah aims to be the default starting point for any property search in Saudi Arabia — the layer a user opens first, before going to any individual platform. By being AI-native and neutral, Ezhalah removes the friction of fragmented search while respecting the listing platforms it depends on.

Product principles

🔍

One search, every source

A single query searches Aqar, Bayut, Gathern, Property Finder, Wasalt and Aldarim simultaneously.

💬

Conversational by default

Users type naturally or answer a short guided interview — no rigid forms required.

⚖️

Neutral & non-advisory

Ezhalah never recommends, ranks by opinion, or advises. It shows listings; the user decides.

↗️

Traffic, not transactions

Every listing tap drives a qualified visitor to the source platform. Ezhalah never intermediates a deal.

Scope of this document

This PRD specifies the MVP as designed in the interactive prototype: a mobile-first (iOS) experience covering search, the Ezhalah AI Agent, the guided question interview, authentication, the sidebar/chat-history, settings, and supporting pages. Backend services, data-ingestion pipelines, and partner API integrations are described at a requirements level and are out of scope for the prototype itself.

02

Problem & opportunity

The problem

  • Fragmentation. Listings are scattered across 6+ platforms with no single search. Users repeat the same query everywhere.
  • Inconsistent filtering. Each platform structures categories, property types, and price/size differently, making cross-platform comparison hard.
  • Search fatigue. Rigid filter forms force users to know exactly what they want before they can search.
  • No natural-language entry. A user who simply wants "a villa in north Riyadh for my family of five" has to translate that into a series of dropdowns.

The opportunity

Two sides both gain from an aggregation layer:

SideTodayWith Ezhalah
Seekers (renters/buyers)Search 6 apps separately; mentally merge results.One conversational search returns unified, ranked results.
Listing platformsCompete for the same users; pay to acquire traffic.Receive qualified, high-intent visitors routed straight to their listings.
Why now

Saudi Arabia's Vision 2030 housing push, REGA's regulated listing ecosystem (FAL licensing), high smartphone penetration, and mature Arabic-capable LLMs make an AI-native, compliant aggregation layer viable for the first time.

03

Goals & non-goals

Goals (MVP)

  1. Let a user find relevant listings across all six sources from a single query — typed naturally or via the guided interview.
  2. Deliver an AI Agent that understands free text, fixes typos, converts currencies/units, and stays strictly on-topic.
  3. Route every listing tap to its original source platform (in-app browser) without intermediating.
  4. Provide lightweight accounts (phone OTP via WhatsApp, Apple, Google) gated behind a single sign-up wall after the first search.
  5. Maintain a Claude-style chat history sidebar so signed-in users can revisit and refine prior searches.
  6. Operate within REGA and PDPL requirements as a neutral search platform.

Non-goals (explicitly out of scope for MVP)

  • No transactions. Ezhalah does not facilitate payments, contracts, deposits, or commissions.
  • No owned inventory. Ezhalah never lists its own properties.
  • No recommendations or advice. The agent never says which property is "best" or gives buying/financial advice.
  • No agent/brokerage tooling (CRM, lead management) in MVP.
  • No web/Android client in MVP — iOS mobile-first only.

05

Feature specifications

The MVP is organized into the feature areas below. Priority: P0 must-have   P1 should-have   P2 nice-to-have

5.1 — Filter search P0

The default home screen. A structured, cascading search card over a Saudi skyline backdrop.

  • Transaction toggle: Rent / Buy. Drives price labels and which listings appear.
  • City / neighborhood field with city-first autocomplete (typing "r" surfaces Riyadh districts; "k" surfaces Khobar — never mixed).
  • Category → Property type cascade. Two categories (Residential, Commercial), each opening its scoped type list as clear, tappable boxes.
  • Type-specific detail: bedrooms for dwellings; realistic size-in-meters ranges (plus a free numeric input) for land/commercial/farm.
  • Price field with automatic thousands separators and magnitude-based interpretation (monthly vs annual rent; total vs price-per-meter for buy), with the calculation shown back to the user.

5.2 — Category & type taxonomy P0

CategoryProperty types
ResidentialApartment, Villa, Floor, House, Room, Building, Residential Land, Rest House, Chalet
CommercialOffice, Warehouse, Shop, Showroom, Workshop, Factory, Commercial Land, Industrial Land, Farm, Agriculture Plot, Camp

Mirrors the structure used by Aqar & Bayut. Size ranges scale realistically per type (e.g. Industrial Land > Commercial Land > Residential Land; Factories > Warehouses > Shops).

5.3 — Ezhalah AI Agent P0

A conversational search mode (detailed in §7). Accepts free-text queries, replies like a real assistant, then presents matching listings. Reachable from the top-right header.

5.4 — Guided question interview P0

Triggered by "Want more accurate results" or by asking the agent to "ask me questions." A staged, conversational interview rather than a single long form.

  • Grouped stages: Location (city → neighborhood) then Details (Rent/Buy → category → type → budget → size). Only un-answered fields are asked; anything provided in the filter or query is pre-filled as a tappable chip.
  • Conversational hand-offs: between groups Ezhalah posts a chat recap ("Good — I see what you're after. City: Riyadh, neighborhood: Al Narjis. Just a few more…") that types out like an AI.
  • Per-question controls: tap an option to advance instantly; a "Something else" row to type a custom answer (with smart type-resolution, e.g. "flat" → Apartment); a centered, bold green Skip button; and a Back button (hidden on a group's first question).
  • Skip = no filter. Skipped fields are simply omitted and broadened — the user always gets results and never hits a dead end.
  • Editable answers: pre-filled chips and answered chips can be tapped to change them (e.g. switch Rent → Buy).

5.5 — Results & listing cards P0

  • Compact horizontal cards: thumbnail, city · district, deal · type · size · beds, price, and "listed … · source."
  • Ranked most-recent; listing dates sequenced (today → 1 year). Save (heart) per card.
  • Heading speaks as Ezhalah ("Ezhalah! Here are…"), with broadened-field notes when fields were skipped.
  • Tapping a card opens the in-app browser showing the listing on its source platform (full-screen, with the platform's domain, branding, photos, specs, description, and Call / WhatsApp actions).

5.6 — Authentication P0

  • Sign-up wall appears after the first search (and re-appears 1 minute after dismissal until the user signs in).
  • Methods: phone (OTP via WhatsApp), Continue with Apple (Face ID + Hide/Share email), Continue with Google (account chooser).
  • Per-country phone validation (Saudi, UAE, Qatar, Bahrain, Kuwait, Oman) with correct prefixes/lengths and the GCC country dropdown.
  • Identity display: phone → "User 3081" (last 4 digits); Apple/Google → real name + email.

5.7 — Sidebar & chat history P1

  • Appears only after sign-in: logo + New Chat, scrollable history grouped Starred / Today / Yesterday / Last 7 Days / Last 30 Days.
  • Each chat labeled with the user's own wording; 3-dot menu to Star / Delete; active chat highlighted. Starred pins to top; unstarred expire after 30 days.
  • Bottom: Settings, Support, About Us, AR/EN toggle, and the user row (avatar + identity) — tapping it opens Settings.

5.8 — Settings P1

  • Opens as a popup over the app (background visible).
  • Display name (editable), and method-specific identity: phone (Change → re-enter number → WhatsApp OTP), or Apple/Google account (read-only, with a note that changing it requires deleting and re-creating the account).
  • Logged-in device (shown, no per-device logout), a single Log out button, and Delete account (confirmation popup).

5.9 — Share P1

iOS-style share sheet from the header: app preview card, app row (WhatsApp, Messages, X, Mail, Notes), and Copy Link, with the share text "Ezhalah — one place to explore all listings and more in seconds. Try now."

5.10 — Support & About P1

  • Support (popup): support@ezhalah.com (account, searches, technical), info@ezhalah.com (business, partnerships, media). Response time: typically 72 hours, up to 1 week.
  • About Us (popup): platform description, "our role" (search only, no ownership/transactions/commission), REGA FAL license, third-party-listing disclaimer, and PDPL data/privacy statement.

5.11 — Feedback P1

After a fully-completed guided interview, a "Were these helpful?" 👍 / 👎 row appears below the results (only on the final result set, not intermediate ones).

5.12 — Localization & safe-area P1

  • AR / EN toggle (Arabic is the primary market language; full RTL is a fast-follow).
  • iPhone-accurate layout: status-bar scrim, home-indicator safe area, single-screen fit for the home/filter view, and a ChatGPT-style keyboard dock for the AI chat.

AI Agent: rules & behavior

The agent is powered by an LLM with a strict system contract. It must feel like a capable assistant while remaining a neutral search tool.

7.1 — Hard rules

Never

Recommend a property · say which is "best / better / good value / a great deal" · give buying or financial advice · make a decision for the user · invent or verify listing facts.

Always

Identify as Ezhalah · stay scoped to Saudi real estate · acknowledge the user naturally, then present matching listings for them to choose · correct typos and units before searching · stay neutral.

7.2 — Behavior matrix

User inputEzhalah responseShows listings?
Real-estate query ("villa in Riyadh")"Ezhalah! Here are…" + cardsYes
Typo ("vila in riyad")"Did you mean 'villa in Riyadh'?" then searchesYes (corrected)
Foreign currency / unit ("20,000 dirhams", "5000 sqft")"20,000 AED ≈ SAR 20,400." then searchesYes (converted)
Advice / comparison ("where should I buy, here or there?")"I can only show listings — I can't recommend. I can show a mix of both areas if you'd like."No (until specified)
Off-topic ("what's the weather?")"I can only help you find real estate across Saudi Arabia. What are you looking for?"No
Distress / harmfulBrief, caring redirect, then steers back to real estate.No

7.3 — Language & tone

  • Warm, concise, plain text — no markdown, no emoji in agent replies.
  • Bilingual (Arabic / English); detects the user's language and responds in kind.
  • Off-topic replies never use the word "Ezhalah!" as a results header (kept exclusively for when listings are shown).
Implementation note

The prototype calls an LLM at runtime for classification + reply, with a deterministic heuristic fallback (typo map, currency/unit tables, on-topic regex) so behavior degrades gracefully if the model is unavailable.

Legal, licensing & compliance

10.1 — Role & disclaimers (in-product)

  • Search platform only. Ezhalah does not own, list, sell, or rent property, does not facilitate transactions, and collects no commission. (Stated on the About page.)
  • Third-party listings. All listings are sourced from partner platforms; Ezhalah does not own or verify any listing. Users are told to confirm details directly with the source before any decision.
  • No advice. The agent's neutrality rules (§7) are themselves a compliance control — Ezhalah gives no investment or purchase advice.

10.2 — REGA / FAL licensing

Ezhalah operates under a REGA FAL license (number to be inserted), issued by the General Authority for Real Estate. The licensing scope for a search/aggregation platform vs. a brokerage must be confirmed with REGA, including how aggregated listings and outbound routing are treated.

10.3 — Data & privacy (PDPL)

  • Compliant with Saudi Arabia's Personal Data Protection Law (PDPL).
  • All user data stored on Saudi servers (data residency).
  • Ezhalah does not sell user data.
  • Minimal data collection: phone/identity for auth, search history for the signed-in experience.
Pre-launch checklist

Finalize REGA license number & scope · execute partner data agreements · confirm WhatsApp Business API for OTP · privacy policy & terms · PDPL data-processing records · Apple/Google sign-in entitlements.

Success metrics (KPIs)

North-star

North-star metric

Qualified listing tap-throughs routed to partner platforms per week — the unit of value for both users (found something worth opening) and partners (received a high-intent visitor).

Supporting metrics

Search → result rate
% of searches that return results the user engages with.
Tap-through rate
% of result sets where ≥1 listing is opened.
Query type mix
Filter vs AI-agent vs guided-interview usage.
Sign-up conversion
% of first-search users who complete auth.
Interview completion
% who finish the guided questions vs drop off.
Returning-search rate
Signed-in users starting a new chat within 7/30 days.
Agent accuracy
On-topic classification & typo/unit fixes (👍/👎 feedback).
Partner coverage
Share of results contributed by each source.

Guardrail metrics

  • Neutrality violations: zero tolerance — any "recommend/best" output is a defect.
  • Gathern-in-Buy leakage: must remain zero.
  • Dead-end searches: % of searches returning no results (target ≈ 0 via broadening).

Roadmap & phases

Phase 0 — Prototype Done

Interactive iOS prototype: filter search, AI Agent, guided interview, auth flows, sidebar/history, settings, support/about, share, in-app browser. (This document describes that build.)

  • Expanded sources & (optionally) a third "Agricultural" category once inventory justifies it.
  • Personalized (still non-advisory) result ordering.

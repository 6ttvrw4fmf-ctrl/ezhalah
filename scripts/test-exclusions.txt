# Checks that deliberately do NOT run in `npm test`, each with WHERE it runs instead.
#
# Format:  filename | where it DOES run | why it is not in npm test
#
# This file is the ONLY way a verify-* check can be absent from `npm test`. Everything else in
# scripts/ that matches verify-*.{ts,mjs} runs automatically, so a barrier cannot go dark by being
# forgotten — only by a deliberate, reviewed line here. An entry naming nowhere is a check that runs
# nowhere, and verify-test-registry-complete.ts fails on it.
#
# The common reason is the same one AGENTS.md gives for the migration drift guard: `npm test` is a
# REQUIRED status check on every PR, so wiring a LIVE production check into it would fail unrelated
# PRs whenever production is momentarily unhealthy — turning a required gate into noise.

# Each line is a `public.<name>` that committed SQL in supabase/migrations/ CALLS, but that no
# committed migration ever CREATES. Every one of them exists only in production: nobody can review
# it, diff it, or restore it from this repository.
#
# HOW THE CLASS SURVIVED. Migration-drift conditions #1-#5 all compare a migration's IDENTIFIERS or
# its text against production, and every one of them grandfathers the pre-strict era
# (missing_in_git below 20260716093330, the other four below STRICT_ERA_BASELINE 20260815000000).
# A function created by a pre-baseline migration that was never committed is therefore invisible to
# all five — which is exactly how prune_inactive_from_search(), the guaranteed remover of inactive
# rows from the served search index, was called by sync_search_listings_ar() and pinned by a barrier
# for two months with no definition anywhere in the tree (ops_incident #26).
#
# THESE ARE EXEMPT SO THE BARRIER CAN EXIST AT ALL, NOT BECAUSE THEY ARE FINE. Reconciling one means
# recovering its CREATE verbatim from supabase_migrations.schema_migrations.statements into
# supabase/migrations/<the applied version>_<the applied name>.sql - then DELETING its line here.
#
# THE RATCHET: entries may only be REMOVED. verify-committed-sql-defines-what-it-calls.ts fails if
# this file grows, so a NEW production-only object cannot be silenced by appending to it. Same shape
# as scripts/test-baseline.txt, scripts/migration-content-parity-baseline.txt and
# STRICT_ERA_BASELINE: history grandfathered, the present held to the rule.
